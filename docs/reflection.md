# Project Reflection

This project taught me that implementing an agent involves both application logic and the constraints of its deployment environment. One early challenge was creating the Knowledge Base. The course specified OpenSearch Serverless, but the lab role lacked permissions needed to provision it. I used a Bedrock Managed Knowledge Base with the product catalog in S3 and verified retrieval through the agent. This preserved the catalog-search capability while making the infrastructure difference explicit.

My main development decision was to integrate and test each capability individually. I checked Gateway tool discovery and order lookup, then refund processing, Knowledge Base retrieval, cross-session memory, loyalty calculations, and browser access. Testing one capability at a time made failures easier to isolate. For example, refund tests exposed the importance of looking up the order total before submitting the refund amount. Memory tests also required separate sessions and time for asynchronous extraction. This approach gave me more useful evidence than trying to debug every capability in a single conversation.

Deployment presented another challenge. CodeBuild repeatedly stopped during provisioning, before the application build began. I could not establish the exact cause from the available diagnostics. I proceeded with direct ZIP deployment through the AWS SDK: packaging Python dependencies for Linux ARM64, adding the agent code, uploading the archive to S3, and creating the AgentCore Runtime with boto3. After the Runtime reached READY, I invoked it through the SDK and captured the required test results. Deployed tests revealed missing Knowledge Base and browser permissions in the Runtime role, which were addressed before repeating those tests successfully.

For production, I would automate these individual checks and the deployment process, add authenticated customer access, and make refunds persistent and idempotent. I would also improve error logging and connect monitoring alarms to notifications. The key lesson was to verify behavior in the deployed environment, even after local tests succeeded.
